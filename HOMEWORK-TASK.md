# Урок 14. Асинхронность и API

## Домашнее задание

### Контрольные вопросы

1. Почему `async`-функция всегда возвращает `Promise`, даже если внутри возвращается обычное значение?
2. Почему переменная `error` в блоке `catch` имеет тип `unknown`, а не `Error`?
3. Зачем создавать собственный класс `ApiError`, если уже существует встроенный класс `Error`?
4. В чём преимущество `Promise.all` по сравнению с последовательным ожиданием нескольких запросов?
5. Зачем понадобилась универсальная функция `request<T>`, если уже существуют `fetchPost` и `fetchUser`?

## Практическое задание

Используя API https://jsonplaceholder.typicode.com и код, полученный на уроке, добавьте поддержку работы с комментариями.

### 1. Опишите модель данных

Создайте тип:

```ts
CommentDto
```

Он должен содержать поля:

* `postId`;
* `id`;
* `name`;
* `email`;
* `body`.

---

### 2. Реализуйте функцию получения комментария

Создайте функцию:

```ts
fetchComment
```

Она должна:

* принимать идентификатор комментария;
* использовать функцию `request<T>`;
* возвращать значение типа:

```ts
Promise<CommentDto>
```

---

### 3. Выполните несколько запросов одновременно

Получите параллельно:

* публикацию с идентификатором `1`;
* пользователя с идентификатором `1`;
* комментарий с идентификатором `1`.

Для этого используйте:

```ts
Promise.all
```

После получения данных выведите в консоль:

* заголовок публикации;
* имя пользователя;
* электронную почту автора комментария.

---

### 4. Обработайте возможные ошибки

Весь код выполнения запросов поместите в блок:

```ts
try...catch
```

Если возникла ошибка типа:

```ts
ApiError
```

выведите в консоль:

* HTTP-статус;
* дополнительные сведения (`details`).

Для остальных ошибок сохраните обработку, реализованную на уроке.
