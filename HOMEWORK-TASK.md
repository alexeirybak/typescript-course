# Урок 10. Дженерики

## Домашнее задание

### Контрольные вопросы

1. Чем `<T>` отличается от `any`?
2. Что даёт ограничение `T extends HasId`?
3. Как связаны `K extends keyof T` и `T[K]`?
4. Когда параметр типа не нужен?
5. Почему `parse<T>` без валидации небезопасен?

## Практическое задание

Создайте небольшую типобезопасную систему управления каталогом товаров.

### 1. Опишите модели данных

Создайте интерфейс сущности:

```ts
interface Entity<TId>
```

На его основе создайте типы:

* `Product`;
* `Category`.

Используйте разные типы идентификаторов:

* у товаров — `number`;
* у категорий — `string`.

---

### 2. Реализуйте generic-класс репозитория

Создайте класс:

```ts
Repository
```

Он должен поддерживать следующие операции:

* сохранение сущности;
* поиск по идентификатору;
* получение всех сущностей;
* удаление по идентификатору;
* проверка существования сущности.

Используйте дженерики так, чтобы репозиторий одинаково хорошо работал и с товарами, и с категориями.

---

### 3. Реализуйте универсальные функции работы с объектами

Создайте функции:

* безопасное получение свойства;
* безопасное обновление свойства.

Они должны работать с любыми объектами и не позволять:

* обращаться к несуществующим свойствам;
* присваивать свойству значение неподходящего типа.

---

### 4. Создайте универсальный тип ответа API

Опишите generic-тип успешного ответа и тип ошибки.

Затем объедините их в общий тип ответа API.

Создайте несколько примеров:

* получение списка товаров;
* получение списка категорий;
* ответ с ошибкой.

---

### 5. Создайте generic-класс кэша

Реализуйте класс:

```ts
Cache
```

Он должен поддерживать методы:

* сохранение значения;
* получение значения;
* удаление значения;
* проверка наличия ключа;
* получение существующего значения или создание нового через функцию-фабрику.

---

### 6. Используйте параметры типов по умолчанию

Создайте generic-тип постраничного ответа.

По умолчанию он должен использовать стандартную информацию о пагинации.

Покажите пример использования:

* со стандартной пагинацией;
* с собственной структурой метаданных.

---

### 7. Найдите плохие дженерики

Рассмотрите следующий код.

Для каждого примера:

* объясните, почему использование дженерика здесь неудачно;
* предложите более удачный вариант реализации.

```ts
function parse<T>(text: string): T;
```

```ts
function length<T extends { length: number }>(value: T): number;
```

```ts
function process<
  T,
  U,
  V,
  W,
  X,
  Y,
  Z
>(...);
```

Не переписывайте код целиком. Достаточно объяснить проблему и описать, как её следует исправить.
