# Урок 7. type, interface и перечисления

## Домашнее задание

### Контрольные вопросы

1. В чем основное отличие `type` от `interface`?
2. Какие типы можно описать через `type`, но нельзя напрямую через `interface`?
3. Что такое declaration merging и для чего оно используется?
4. Что делает ключевое слово `implements`?
5. Чем обычный `enum` отличается от `const enum`?
6. В чем преимущества литерального объединения перед строковым `enum`?
7. Как получить union-тип из объекта, объявленного с `as const`?

### Практическое задание

#### Задание 1

Смоделируйте систему документов.

Создайте общий интерфейс:

```ts
interface DocumentBase
```

с полями:

- `id`;
- `author`;
- `createdAt`.

На его основе создайте три типа документов:

- `Article`;
- `Video`;
- `Podcast`.

Используйте литеральное поле `type`, чтобы различать варианты.

---

#### Задание 2

Создайте объект статусов публикации:

```ts
const DocumentStatus = {
  Draft: "draft",
  Published: "published",
  Archived: "archived",
} as const;
```

Получите из него тип `DocumentStatus`.

Используйте этот тип в модели документа.

---

#### Задание 3

Создайте интерфейс

```ts
interface Publishable
```

с методом

```ts
publish(): void;
```

Создайте класс `Article`, который реализует этот интерфейс.

---

#### Задание 4

Напишите функцию

```ts
getDocumentInfo(document);
```

которая принимает объединённый тип документов и возвращает строку с основной информацией.

Используйте поле `type`, чтобы определить конкретный вариант документа.

---

#### Дополнительное задание ⭐

Одну и ту же модель ролей пользователей реализуйте тремя способами:

- через строковый `enum`;
- через литеральное объединение;
- через объект `as const` и автоматически выведенный тип.

Сравните эти варианты и кратко ответьте:

- какой проще читать;
- какой не создает дополнительного JavaScript;
- какой вариант вы бы использовали в новом проекте и почему.
