# Урок 13. Модули, декларации и типизированные библиотеки

## Домашнее задание

### Контрольные вопросы

1. Чем именованный экспорт отличается от `default export`?
2. Как импортировать сущность, экспортированную через `default export`?
3. Для чего в проекте создают публичную точку входа `index.ts`?
4. Почему внешнему коду лучше импортировать сущности из `index.ts`, а не из внутренних файлов библиотеки?
5. Для чего нужны файлы деклараций `.d.ts`?
6. Чем файл `.d.ts` отличается от обычного файла `.ts`?
7. Какие настройки `tsconfig.json` включают генерацию деклараций и карт деклараций?
8. Что означает ключевое слово `declare`?
9. Почему объявление через `declare` не создаёт JavaScript-код?
10. Откуда TypeScript получает типы для JavaScript-библиотеки `lodash`?

## Практическое задание

Создайте небольшую библиотеку для работы с товарами и заказами.

Библиотека должна:

* состоять из нескольких модулей;
* использовать именованные экспорты и `default export`;
* иметь публичную точку входа `index.ts`;
* генерировать файлы деклараций `.d.ts`;
* использовать внешнюю типизированную библиотеку `lodash`.

### 1. Создайте структуру проекта

Создайте следующую структуру:

```text
src/
    app.ts
    index.ts
    domain/
        product.ts
        order.ts
    services/
        product-service.ts
        order-service.ts
```

---

### 2. Опишите модель товара

В файле:

```text
src/domain/product.ts
```

создайте тип:

```ts
Product
```

Он должен содержать:

* `readonly id` — числовой идентификатор;
* `title` — название товара;
* `price` — цена;
* `category` — категория товара;
* `available` — доступен ли товар для заказа.

Используйте следующие категории:

```ts
"electronics" | "clothing" | "books"
```

Экспортируйте `Product` с помощью именованного экспорта.

Создайте функцию:

```ts
createProduct
```

Она должна принимать все данные товара и возвращать объект типа `Product`.

Экспортируйте функцию с помощью именованного экспорта.

---

### 3. Опишите модель заказа

В файле:

```text
src/domain/order.ts
```

создайте тип:

```ts
OrderItem
```

Он должен содержать:

* `product` — товар;
* `quantity` — количество единиц товара.

Создайте тип:

```ts
Order
```

Он должен содержать:

* `readonly id` — строковый идентификатор;
* `items` — массив позиций заказа;
* `createdAt` — дата создания.

Экспортируйте оба типа с помощью именованных экспортов.

Создайте функцию:

```ts
createOrder
```

Она должна принимать:

* идентификатор заказа;
* массив позиций.

Функция должна возвращать объект типа `Order`.

Экспортируйте функцию с помощью именованного экспорта.

---

### 4. Создайте сервис товаров

В файле:

```text
src/services/product-service.ts
```

создайте класс:

```ts
ProductService
```

Класс должен хранить массив товаров.

Добавьте методы:

```ts
getAll()
```

```ts
findById(id)
```

```ts
getAvailable()
```

Метод `getAll` должен возвращать все товары.

Метод `findById` должен возвращать товар или `undefined`.

Метод `getAvailable` должен возвращать только товары, у которых:

```ts
available === true
```

Экспортируйте `ProductService` через:

```ts
export default
```

---

### 8. Переведите приложение на публичную точку входа

Измените импорты в файле:

```text
src/app.ts
```

Все сущности библиотеки должны импортироваться только из:

```ts
"./index.js"
```

В `app.ts` не должно остаться импортов из:

```text
./domain/
```

или:

```text
./services/
```

Пример:

```ts
import {
  createProduct,
  createOrder,
  ProductService,
  OrderService,
  type Product,
  type OrderItem,
} from "./index.js";
```

### 13. Настройте генерацию деклараций

В файле:

```text
tsconfig.json
```

включите:

```json
{
  "compilerOptions": {
    "declaration": true,
    "declarationMap": true
  }
}
```

Убедитесь, что также настроена папка результата:

```json
{
  "compilerOptions": {
    "outDir": "./dist"
  }
}
```

---

### 14. Сгенерируйте декларации

Выполните команду:

```bash
npx tsc
```

```text
dist/
```

```text
        order.d.ts

        product-service.d.ts
```

### 17. Используйте `declare`

Создайте файл:

```text
types/environment.d.ts
```

Добавьте глобальное объявление константы:

```ts
declare const APP_VERSION: string;
```

В файле:

```text
src/app.ts
```

обратитесь к:

```ts
APP_VERSION
```

Убедитесь, что TypeScript знает тип этой переменной и не сообщает об ошибке.

Ответьте в комментарии:

```ts
// Создаёт ли declare реальное значение APP_VERSION во время выполнения?
```

Не запускайте этот код до тех пор, пока не будет добавлена реальная переменная.

---

### 19. Итоговая проверка

После выполнения задания убедитесь, что:

* модели находятся в отдельных модулях;
* именованные экспорты используются для типов и функций;
* `ProductService` экспортируется через `default export`;
* `index.ts` является единой публичной точкой входа;
* `app.ts` импортирует внутренние сущности только из `index.ts`;
* `lodash` подключён вместе с `@types/lodash`;
* после `npx tsc` создаются файлы `.d.ts`;
* декларации содержат типы, но не содержат реализацию;
* объявление через `declare` не создаёт реальное значение во время выполнения.
