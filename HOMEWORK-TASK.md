# Урок 12. Встроенные utility types

## Домашнее задание

### Контрольные вопросы

1. Чем `Partial<T>` отличается от `Required<T>`?
2. Почему `Readonly<T>` не делает вложенные объекты полностью неизменяемыми?
3. Когда удобнее использовать `Pick<T, K>`, а когда `Omit<T, K>`?
4. Чем `Omit<T, K>` отличается от `Exclude<T, U>`?
5. Для чего используется `Record<K, V>`?
6. Чем `Extract<T, U>` отличается от `Exclude<T, U>`?
7. Что удаляет `NonNullable<T>`?
8. Чем `Parameters<T>` отличается от `ReturnType<T>`?
9. Для чего используются `ConstructorParameters<T>` и `InstanceType<T>`?
10. Чем `ReturnType<T>` отличается от `Awaited<ReturnType<T>>`?

## Практическое задание

Создайте типобезопасную систему управления товарами интернет-магазина.

Все вспомогательные типы должны быть получены из исходных моделей с помощью встроенных utility types TypeScript.

Не дублируйте свойства вручную там, где новый тип можно понятно получить из уже существующего.

### 1. Опишите модель товара

Создайте тип:

```ts
type Product
```

Он должен содержать:

* `readonly id` — числовой идентификатор;
* `title` — название товара;
* `description` — описание;
* `price` — цена;
* `costPrice` — внутренняя себестоимость;
* `status` — статус товара;
* `category` — категория;
* необязательное поле `imageUrl`;
* `readonly createdAt` — дата создания.

Используйте следующие статусы:

```ts
"draft" | "published" | "archived"
```

Используйте следующие категории:

```ts
"electronics" | "clothing" | "books"
```

### 2. Создайте тип товара для списка

```ts

```

Создайте объект, соответствующий типу `ProductListItem`.

### 3. Создайте публичную модель товара

На основе `Product` создайте тип:

```ts

```

Он должен содержать все свойства товара, кроме внутренней себестоимости `costPrice`.

Используйте:

```ts

```

Проверьте, что объект типа `PublicProduct` нельзя создать со свойством `costPrice`.

### 4. Создайте команду добавления товара

Создайте тип:

```ts

```

Клиент не должен передавать:

* `id`;
* `createdAt`;
* `status`.

Остальные свойства должны соответствовать модели `Product`.

Используйте `Omit`.

Создайте пример правильной команды создания товара.

### 5. Создайте команду обновления товара

Создайте тип:

```ts
UpdateProductCommand
```

Команда должна содержать:

* обязательный `productId`;
* необязательные поля, которые разрешено изменять.

Разрешите изменять:

* `title`;
* `description`;
* `price`;
* `category`;
* `imageUrl`.

Запретите изменять:

* `id`;
* `createdAt`;
* `costPrice`;
* `status`.

Для получения изменяемых полей используйте комбинацию:

```ts
Pick
```

```ts
Partial
```

Добавьте `productId` отдельно.

Создайте несколько примеров команд:

```ts
const updateTitle
```

```ts
const updatePrice
```

```ts
const updateSeveralFields
```

### 11. Создайте команду публикации товара

Создайте тип:

```ts
PublishProductCommand
```

Он должен содержать:

* `productId` с типом идентификатора товара;
* `status`, в который нельзя передать `"draft"`.

Тип идентификатора получите через indexed access:

```ts
Product["id"]
```

Тип статуса получите с помощью:

```ts
Exclude
```

Пример правильной команды:

```ts
const publishCommand: PublishProductCommand = {
  productId: 1,
  status: "published",
};
```

Проверьте, что значение `"draft"` вызывает ошибку TypeScript.

### 14. Создайте функцию-обёртку

Создайте функцию:

```ts
function withLogging(...)
```

Она должна:

* принимать функцию;
* выводить её аргументы в консоль;
* вызывать исходную функцию;
* выводить результат;
* возвращать результат.

Обёртка должна сохранять типы параметров и результата исходной функции.

Примените её к функции `createProduct`:

```ts
const loggedCreateProduct =
  withLogging(createProduct);
```

Проверьте, что `loggedCreateProduct` принимает только правильную команду создания товара и возвращает `Product`.

### 16. Получите результат асинхронной функции

Создайте асинхронную функцию:

Получите тип:




```ts
LoadedProducts
```

```ts
Awaited<ReturnType<typeof loadProducts>>
```



### 18. Итоговая проверка

Добавьте новый статус товара:

```ts
"outOfStock"
```

После изменения исходного типа проверьте, какие части программы потребуют обновления.

TypeScript должен потребовать добавить новый статус как минимум в объекты, построенные с помощью:

```ts
Record<ProductStatus, ...>
```

Вручную изменять вычисляемые типы нельзя.

Все они должны автоматически обновиться после изменения исходной модели `Product`.
